## 5. Windows 설치·빌드: 실제 오류와 해결

테스트 환경은 Windows PowerShell, Node.js 24, npm 12였습니다. 이 셸을 CMD와 혼동하지 마세요.

### 오류 1: npm의 Git 의존성 차단

`npm.cmd ci`가 다음 오류로 실패했습니다.

```text
npm error code EALLOWGIT
npm error Fetching packages of type "git" have been disabled
```

직접 Git에서 가져오는 의존성은 `three-kawase-blur`입니다.

- package.json: `github:ycw/three-kawase-blur`
- 당시 lockfile 참조: `git+ssh://git@github.com/ycw/three-kawase-blur.git#9b69ca5d3f7ec7b8eabd60d50292c64ee07da560`

npm 12의 Git 의존성 기본 차단을 고려해야 합니다. 당시 해결은 **현재 설치 명령에서 프로젝트가 직접 선언한 Git 의존성을 허용**하는 `--allow-git=root`였습니다. Git SSH URL을 HTTPS로 받게 하는 설정도 해당 PowerShell 세션에 적용했습니다.

### 오류 2: 설치 실패 후 npx가 다른 Vite를 받음

설치가 실패한 뒤 `npx.cmd vite build`를 실행하자 Vite `8.3.6`을 임시로 받아 실행했고, 프로젝트 안의 `vite`와 `@vitejs/plugin-react`를 찾지 못했습니다.

설치 성공을 먼저 확인하고, **프로젝트에 설치된 Vite를 직접 실행**하는 방식으로 해결했습니다. 이 상황에서 임시 다운로드한 최신 Vite를 원본 프로젝트의 정상 설치 버전으로 취급하지 마세요.

### 성공 확인을 받은 PowerShell 명령

먼저 현재 프로젝트 루트로 이동한 뒤 실행합니다. `& { ... }` 블록으로 묶어 설치 실패 시 후속 빌드가 계속되지 않게 했습니다.

```powershell
& {
    $ErrorActionPreference = "Stop"

    $env:GIT_CONFIG_COUNT = "1"
    $env:GIT_CONFIG_KEY_0 = "url.https://github.com/.insteadOf"
    $env:GIT_CONFIG_VALUE_0 = "ssh://git@github.com/"

    npm.cmd ci --allow-git=root
    if ($LASTEXITCODE -ne 0) {
        throw "설치에 실패했습니다."
    }

    node .\node_modules\vite\bin\vite.js build
    if ($LASTEXITCODE -ne 0) {
        throw "빌드에 실패했습니다."
    }
}
```

`npm.cmd`를 사용한 이유는 PowerShell의 npm.ps1 실행 정책 문제를 피하기 위해서입니다. 실행 정책 변경은 필요하지 않았습니다.

로컬 미리보기:

```powershell
npm.cmd run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

로컬 PC 접속: http://127.0.0.1:4173  
종료: Ctrl+C. 배치 작업 종료 질문이 나올 수 있습니다. 위 주소와 포트는 개발용 로컬 미리보기 예시이며 실제 운영 접속 정보가 아닙니다.

`npm run build`의 원본 스크립트는 `npm cache clean --force && vite build`입니다. 이번 테스트에서는 캐시 전체 정리 없이 Vite를 직접 실행했습니다. 저장소의 Worker용 스크립트를 이번 게시 테스트에서 사용한 것은 아닙니다.

`npm warn deprecated`는 당시 설치 실패의 직접 원인이 아니었습니다. EPERM 정리 경고도 있었지만 확정된 설치 중단 원인은 EALLOWGIT였습니다. 경고와 최종 실패 원인을 구분하세요.

### 오류 3: Windows 압축 실패

압축 명령 뒤 검사에서 “압축에 실패했습니다”가 나왔으나 상세 원인이 출력되지 않아 원인을 확정하지 못했습니다.

해결은 **압축을 생략하고 빌드 출력 디렉터리를 직접 전송**하는 것이었습니다. 원인이 도구 버그, 권한, 경로, 종료 코드 중 무엇이었다고 단정하지 마세요.

- 로컬 응답과 실제 브라우저 화면은 별도로 확인해야 합니다. HTTP 200만으로 WebGL 렌더링 성공을 판단하지 마세요.
- 사용자 확인은 게시 내용 변경과 기존 홈페이지 표시 복구입니다. 자동 배포, 전체 운영 점검, 이전 파일 목록과 완전히 동일한 복구까지 검증한 것은 아닙니다.
- 과거 초기 환경 명세와 후속 운영 상태에 차이가 있었습니다. 초기 문서만 보고 새로 설치하거나 재구성하지 말고, 실제 작업 시 최신 비공개 운영 자료를 확인해야 합니다.

실제 접속 주소, 서버 사양·내부 경로·서비스명·컨테이너·포트·인증 및 배포/복구 명령은 사용자 선택에 따라 이 문서에서 제외했습니다. 이를 추측해서 채우거나 후속 커밋에 되살리지 마세요.

## 7. 아직 완료하지 않은 일

- 사용자 고유의 다락방 공간 설계·Blender 제작·웹용 GLB 반입.
- 개인 소개, 프로젝트, 연락처, 메타데이터 등 콘텐츠 교체.
- 오브젝트별 기능과 카메라 목표·이동 방식 확정.
- Blender 오브젝트·카메라 목표·클릭 영역 규칙 확정.
- 모바일·접근성·로딩·성능의 구체적 목표 및 검증.
- 자동 배포, 배포 버전 관리, 백업 보존 정책.

이 항목은 후속 작업 후보입니다. 모두 한꺼번에 구현하라는 요청이 아닙니다. Antigravity에서 사용자가 다음으로 요청하는 범위에 맞춰 진행하세요.

## 8. 다음 에이전트의 첫 작업

1. 루트 AGENTS.md와 이 문서를 읽습니다.
2. 작업 중인 브랜치와 사용자 변경을 확인합니다.
3. 현재 원본 모델과 코드의 연결 방식을 파악합니다.
4. “디자인은 사용자 주도 / 현재 코드는 원본 기반 / 게시와 복구는 검증 완료”를 유지합니다.
5. 사용자가 인수인계만 요청했다면 이해한 상태를 요약하고 다음 요청을 받습니다. 자동 재배포하지 않습니다.
6. 새 기능을 구현했다면 변경된 동작에 맞는 빌드·브라우저 확인을 하고, 사용자 확인과 에이전트 검증을 구분해 기록합니다.

사용자는 한국어로 소통하며, 명령을 안내할 때 어느 PC·셸·계정에서 실행하는지 구체적인 설명이 필요했습니다. PowerShell과 CMD 문법을 구분해 안내하세요.
